# 0.3.1 — 2026-09-24

## Changed

- **`fema_search_nfip` paging** — new `offset` input. Claims come newest loss first with `id` breaking ties, and every inline page, with or without DataCanvas, stops at 100,000 characters of claims (about 330), with a `notice` naming the offset to continue from ([#22](https://github.com/cyanheads/fema-mcp-server/issues/22), [#37](https://github.com/cyanheads/fema-mcp-server/issues/37)).
- **`fema_search_nfip` canvas staging** — a canvas is acquired only at `offset` 0, once the first page shows the match overflows the inline budget; a later `offset` never stages a canvas, and a canvas minted for a failed stage is dropped ([#5](https://github.com/cyanheads/fema-mcp-server/issues/5)).
- **`fema_search_nfip` spill guidance** — the spill `notice`, the text output, and the `canvas_id`/`canvas_table`/`spilled` descriptions name `fema_dataframe_describe` before `fema_dataframe_query` ([#26](https://github.com/cyanheads/fema-mcp-server/issues/26)).
- **`fema_search_disasters` capped window** — past 10,000 matching designated-area rows, the declarations dated on the window's oldest day are dropped, so every returned declaration is complete; the response sets `truncated: true`, words its totals as lower bounds, and its `notice` names the `date_to` that continues with older declarations ([#21](https://github.com/cyanheads/fema-mcp-server/issues/21)).
- **`fema_query_dataset` `dataset_not_served`** — a catalog-listed dataset whose endpoint 404s now fails with this new reason instead of `unknown_dataset`, and without spelling advice ([#33](https://github.com/cyanheads/fema-mcp-server/issues/33)).

## Fixed

- **`fema_search_nfip` `total_count`** is OpenFEMA's match count on every path; a spill at the 50,000-row cap reported the staged row count instead. The new `staged_count` gives the rows on the canvas table ([#36](https://github.com/cyanheads/fema-mcp-server/issues/36)).
- **`fema_query_dataset`** resolves a dataset by its catalog `name` as well as its `webService` path, so `DataSetFields` and `OpenFemaDataSets` return rows at v1 ([#33](https://github.com/cyanheads/fema-mcp-server/issues/33)).
- **`fema_search_nfip` `cause_of_damage` and `occupancy_type`** descriptions list OpenFEMA's published codes, including the Risk Rating 2.0 occupancy codes `11`–`19`; the values pass through unchanged ([#35](https://github.com/cyanheads/fema-mcp-server/issues/35)).
- **Zero counts and amounts** — output descriptions on `fema_get_housing_assistance`, `fema_get_public_assistance`, and the `fema_search_nfip` payment fields say `0` where they claimed a zero value was absent; the housing `zip_code` descriptions name `00000`, OpenFEMA's code for records filed under no ZIP code.
