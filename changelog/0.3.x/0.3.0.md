# 0.3.0 — 2026-09-23

## Changed

- **Breaking — `fema_search_disasters` `date_from`/`date_to`** accept only a real calendar date in `YYYY-MM-DD` form ([#31](https://github.com/cyanheads/fema-mcp-server/issues/31)). Forms OpenFEMA used to accept and misread (`2024`, `2024-01`, `2024-02-30`) are rejected as invalid arguments before any request; an empty string still counts as omitted. Migration: send full dates, e.g. `2024-12-31` rather than `2024`.
- **`FEMA_BASE_URL`** is the API root, default `https://www.fema.gov/api/open`; each dataset's version is appended per request, and a trailing `/v<N>` on an existing override is dropped ([#27](https://github.com/cyanheads/fema-mcp-server/issues/27)). A value that is not a URL now fails at startup.
- **`fema://disaster/{disasterNumber}`** declares a `not_found` error contract: malformed, out-of-range (above 32767), and unknown numbers fail with a recovery pointing to `fema_search_disasters`, and trailing characters (`4781abc`) no longer resolve to a disaster ([#24](https://github.com/cyanheads/fema-mcp-server/issues/24)).
- **Release process** — every release goes through a gated release PR: a `release-pr-review` pass on the open PR precedes `release-and-publish`.

## Fixed

- **`fema_query_dataset`** queries each dataset at the version the OpenFEMA dataset catalog lists (highest listed wins, cached 6 hours), so v1-, v3-, and v4-only datasets such as `FemaWebDeclarationAreas` and `NfipClaims` return rows instead of `unknown_dataset` ([#27](https://github.com/cyanheads/fema-mcp-server/issues/27)). A name the catalog does not list fails `unknown_dataset` without a data request, naming the catalog spelling on a case-only mismatch; a catalog that cannot be read with nothing cached fails `catalog_unavailable` (retryable).
- **OpenFEMA 400 errors** are classified by the failing clause into `invalid_filter`, `invalid_select`, `invalid_orderby`, or `invalid_odata_syntax`, with messages naming the parameter and field ([#29](https://github.com/cyanheads/fema-mcp-server/issues/29)). An out-of-range integer on a field other than `disasterNumber` no longer reports an out-of-range disaster number.
- **`fema_search_nfip`** reads `NfipClaims` v3 in place of `FimaNfipClaims` v2, which OpenFEMA froze on 2026-06-01 and removes on 2026-10-15 ([#30](https://github.com/cyanheads/fema-mcp-server/issues/30)); output fields and canvas columns are unchanged.
- **`fema_get_public_assistance`, `fema_get_housing_assistance`** — a `disaster_number` above 32767 fails as a declared `not_found` with `fema_get_disaster`'s recovery, before any request ([#23](https://github.com/cyanheads/fema-mcp-server/issues/23)).
- **`fema_get_housing_assistance`** text output states `owners_count` and `renters_count` on every response, including when either records array is empty ([#25](https://github.com/cyanheads/fema-mcp-server/issues/25)).
- **Paging past the end** — on `fema_search_disasters`, `fema_get_public_assistance`, `fema_get_housing_assistance`, and `fema_query_dataset`, an `offset` at or past a non-zero total returns the empty page with its totals and a `notice` naming the last valid offset, instead of `no_results` or a no-records notice ([#32](https://github.com/cyanheads/fema-mcp-server/issues/32)).
