# 0.1.10 — 2026-07-04

## Changed

- **`fema_search_nfip` `zip_code`** — tightened to `z.string().regex(/^\d{5}$/)`; a malformed ZIP is now rejected at the Zod layer instead of silently matching zero rows.

## Fixed

- **Declaration-type render prefixes** — `fema_search_disasters` and `fema_get_disaster` no longer hardcode `DR-`; `format()` interpolates the record's real `declaration_type` (`FM-<n>`, `EM-<n>`, `DR-<n>`) and falls back to a type-agnostic `Disaster #<n>` label when none is present. `fema_get_public_assistance` and `fema_get_housing_assistance` — whose records carry no declaration-type field — always render the type-agnostic form ([#11](https://github.com/cyanheads/fema-mcp-server/issues/11)).
- **State-code validation** — `fema_get_public_assistance`, `fema_get_housing_assistance`, and `fema_search_nfip` now reject unknown state/territory codes with a consistent `invalid_state` `ValidationError`, matching `fema_search_disasters`. The shared `US_STATES` set moved to `src/services/openfema/us-states.ts`; the README's typed-error-contracts bullet no longer lists the nonexistent `state_required` reason ([#12](https://github.com/cyanheads/fema-mcp-server/issues/12)).
- **`fema_search_nfip` empty results** — throws a typed `no_results` `NotFound` error with a recovery hint instead of a silent `0 of 0` success, matching the other three state-scoped search tools ([#13](https://github.com/cyanheads/fema-mcp-server/issues/13)).

## Security

- **`bun audit`** now reports zero advisories (was 7). The `@cyanheads/mcp-ts-core` bump resolves `hono` to 4.12.27, clearing one high-severity CORS-reflection advisory ([GHSA-88fw-hqm2-52qc](https://github.com/advisories/GHSA-88fw-hqm2-52qc)) and four moderate `hono` advisories ([GHSA-wwfh-h76j-fc44](https://github.com/advisories/GHSA-wwfh-h76j-fc44), [GHSA-j6c9-x7qj-28xf](https://github.com/advisories/GHSA-j6c9-x7qj-28xf), [GHSA-rv63-4mwf-qqc2](https://github.com/advisories/GHSA-rv63-4mwf-qqc2), [GHSA-wgpf-jwqj-8h8p](https://github.com/advisories/GHSA-wgpf-jwqj-8h8p)). The lockfile refresh also drops the transitive `esbuild` resolution that carried one low-severity advisory ([GHSA-g7r4-m6w7-qqqr](https://github.com/advisories/GHSA-g7r4-m6w7-qqqr)).
