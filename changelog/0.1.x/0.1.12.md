# 0.1.12 — 2026-07-09

## Added

- **`fema_search_disasters`** — output gains `total_declarations`, the distinct-declaration count before offset/limit paging (a floor rather than an exact total when `total_area_rows` hits the 10,000-row overfetch cap) ([#17](https://github.com/cyanheads/fema-mcp-server/issues/17)).

## Changed

- **`fema_search_disasters`** — `ctx.enrich.total()` now reports the unique-declaration count (`disasterMap.size`) instead of the raw designated-area row count, aligning the framework pagination total with declaration-level paging. The `format()` header changes from "N unique declaration(s)" to "N of T unique declaration(s)" ([#17](https://github.com/cyanheads/fema-mcp-server/issues/17)).

## Fixed

- **`fema_query_dataset`** — `format()` rendered only the first six selected fields per row once a result exceeded 50 rows; `structuredContent` carried the full record but `content[]` silently dropped everything past the sixth field. All selected fields now render for every row ([#18](https://github.com/cyanheads/fema-mcp-server/issues/18)).
- **`fema_get_housing_assistance`** — the `**State:** | **Disaster:**` line was gated on `if (state)` in both the owner and renter sections, so a sparse record missing state — heading on county/city/ZIP instead — dropped the disaster number, the join key to the PA and search tools, from `content[]` entirely. The line now always renders, falling back to a disaster-number-only form when state is absent ([#20](https://github.com/cyanheads/fema-mcp-server/issues/20)).
