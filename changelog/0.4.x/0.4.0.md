# 0.4.0 — 2026-10-16

## Added

- **`next_offset`** on `fema_query_dataset`, `fema_search_disasters`, `fema_get_public_assistance`, `fema_get_housing_assistance`, and `fema_search_nfip` — the offset to continue from while matching rows remain ([#46](https://github.com/cyanheads/fema-mcp-server/issues/46)).
- **`fema_get_housing_assistance` `county` and `zip_code` filters**, applied to both datasets before paging, with `county_filter` and `zip_code_filter` echoed in enrichment ([#47](https://github.com/cyanheads/fema-mcp-server/issues/47)).
- **Housing inspection fields** — owners and renters gain `total_inspected`; owners gain `average_fema_inspected_damage`, `total_damage`, and `no_fema_inspected_damage`; renters gain damage-degree counts and `repair_replace_amount` ([#47](https://github.com/cyanheads/fema-mcp-server/issues/47)).
- **`matched_areas`** on `fema_search_disasters` — with `county` set, each matched area with its FIPS codes and its own IA/PA/HM flags ([#42](https://github.com/cyanheads/fema-mcp-server/issues/42)).
- **Error reasons** — `invalid_county_code` on `fema_search_nfip` ([#45](https://github.com/cyanheads/fema-mcp-server/issues/45)); `invalid_range` on `fema_search_nfip` and `fema_search_disasters` ([#45](https://github.com/cyanheads/fema-mcp-server/issues/45)); `request_too_long` on `fema_query_dataset`, `fema_search_disasters`, `fema_get_public_assistance`, and `fema_get_housing_assistance`, and `filter_too_complex` on `fema_query_dataset` ([#48](https://github.com/cyanheads/fema-mcp-server/issues/48)).
- **`bun run vocabulary:build`** — regenerates the bundled county and incident-type name snapshot from live OpenFEMA.

## Changed

- **BREAKING: `fema_dataframe_query` refuses `current_setting`, `current_schema`, `current_schemas`, `in_search_path`, `query_table`, `read_duckdb`, and `query()` with anything but a single string literal, as `denied_function`** — the stricter canvas SQL gate in `@cyanheads/mcp-ts-core` 0.13.15. `SELECT * FROM query_table('claims')` returned the staged rows on 0.3.2 and is now rejected.
- **Response budget** — every row-returning tool holds a page to 100,000 characters of rows, cut between whole rows, with the remainder named in `next_offset` and `notice` ([#46](https://github.com/cyanheads/fema-mcp-server/issues/46)).
- **`fema_get_public_assistance` and `fema_get_housing_assistance` `limit`** accepts up to 10,000 (was 1,000); housing cuts owners and renters at the same row count, so one `offset` continues both ([#46](https://github.com/cyanheads/fema-mcp-server/issues/46)).
- **`fema_dataframe_query`** sets `truncated` and `shown` on a budget cut; `cap` appears only when the canvas row limit applied ([#46](https://github.com/cyanheads/fema-mcp-server/issues/46)).
- **`fema_query_dataset`** reads its page in up to three budget-sized chunks instead of one request at `limit` ([#46](https://github.com/cyanheads/fema-mcp-server/issues/46)).
- **`fema_dataframe_drop`** re-raises `canvas_not_found` with a drop-specific recovery hint.
- **Framework adoption** — `@cyanheads/mcp-ts-core` 0.13.15 sync of skills, `scripts/check-framework-antipatterns.ts`, `.env.example` (`LOG_LLM_INTERACTIONS`), and Docker base images.
- **Documentation** — README, `docs/design.md`, and agent instructions cover the budgets, filters, and error reasons above.

## Fixed

- **Case-insensitive filters** — `incident_type` and `county` on `fema_search_disasters`, `county` on `fema_get_public_assistance`, and `county` on `fema_get_housing_assistance` match regardless of case, with substring semantics kept, via a bundled name vocabulary ([#41](https://github.com/cyanheads/fema-mcp-server/issues/41)).
- **`fema_search_disasters` with `county`** keeps whole-declaration `designated_area_count` and program flags, read in a follow-up `disasterNumber in (…)` request under one 50-second deadline. If that read fails, `area_totals_unavailable` and a caller-facing cause disclose the matched-area fallback ([#42](https://github.com/cyanheads/fema-mcp-server/issues/42)).
- **Table cells** — `fema_query_dataset` and `fema_dataframe_query` share one renderer: nested values as JSON, `null` distinct from `""`, pipes and line breaks escaped ([#43](https://github.com/cyanheads/fema-mcp-server/issues/43)).
- **PA field descriptions** — `total_obligated`, `project_amount`, `project_size`, and `project_status` match FEMA's definitions ([#44](https://github.com/cyanheads/fema-mcp-server/issues/44)).
- **`fema_search_nfip` `county_code`** is zero-padded and state-prefixed, and a malformed code fails as `invalid_county_code`; a reversed `year_from`/`year_to` or `date_from`/`date_to` fails as `invalid_range`; an empty match names a state/county prefix mismatch ([#45](https://github.com/cyanheads/fema-mcp-server/issues/45)).
- **`fema_dataframe_query` error contract** declares exactly the ten reasons its call path returns; `invalid_query` is gone ([#38](https://github.com/cyanheads/fema-mcp-server/issues/38)).
- **Oversized filters** — an over-long request URL fails as `request_too_long` and a filter nested past 100 levels as `filter_too_complex`, not as a missing dataset or a quoting error ([#48](https://github.com/cyanheads/fema-mcp-server/issues/48)).
- **Retired dataset versions** — `fema_query_dataset` fails as `dataset_not_served` naming the replacement dataset instead of reporting paging past the end; deprecated versions that still serve records add OpenFEMA's notice ([#51](https://github.com/cyanheads/fema-mcp-server/issues/51)).
